# Инструкции для всех агентов Spanish Reader

Обязательны для OpenCode, Codex, Claude Code и других исполнителей. Не зависят от модели или harness.

## Перед началом
- Прочитай [docs/PROJECT_STATE.md](docs/PROJECT_STATE.md) и конкретное назначенное задание. Проверь git status, ветку, базовый SHA и доступное окружение. Не начинай соседнюю задачу и не перезапускай активный эксперимент.
- Источники требований: [SPEC.md](SPEC.md), [DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md). Технические эксперименты: [POC_PLAN.md](docs/POC_PLAN.md), [prompts](docs/prompts/). История решений: [TECHNICAL_DECISIONS.md](docs/TECHNICAL_DECISIONS.md). Фактическая архитектура: [ARCHITECTURE.md](docs/ARCHITECTURE.md). Полный регламент: [DEVELOPMENT_WORKFLOW.md](docs/DEVELOPMENT_WORKFLOW.md).
- Старый [аудит](docs/TECHNICAL_AUDIT.md) описывает донора, не заменяет актуальную SPEC. Не выдавай предложения за утверждённые решения.

## Работа с кодом
- Один пишущий агент на ветку/worktree. Не трогай чужие незакоммиченные файлы и активные worktrees. Не используй destructive reset, force push, автоматическое разрешение конфликтов. Сохраняй checkpoint commit; push/merge только с явного разрешения.
- Выполняй команды сам. Запрашивай разрешение на существенные загрузки/установки, системные изменения, повышение привилегий, платные запросы, доступы и публикацию, если они не согласованы. Не проси владельца вручную выполнять то, что можешь выполнить в своём окружении.
- Не изменяй SPEC, общие контракты, критерии или тесты ради прохождения сборки. Отклонения и архитектурные решения согласуются отдельно.
- Цель: нативный Kotlin/Compose, offline-first, пользовательские данные отдельно от языковой базы и кеша; LLM только по явному запросу по умолчанию; никакого обязательного backend. Не переносить старые статусы/UX донора автоматически.

## Проверка и безопасность
- Никаких секретов, личных текстов, больших SQLite/моделей/APK, нелицензированных данных и чувствительных логов в Git. Проверяй .gitignore и diff перед коммитом. Не выводи ключи. Для донорского кода фиксируй SHA и лицензии, сохраняй notices.
- Запускай реальные тесты; записывай команды, exit codes, окружение, измерения, ссылки на evidence. Mock, Mac, эмулятор, телефон и live API — разные уровни проверки. Не называй незапущенный тест успешным. Если есть блокер, выполняй независимые части.
- Два содержательных тупика без прогресса — checkpoint и handoff; не повторяй одно и то же. Немедленно эскалируй риск потери данных, безопасности или изменения требований.

## Завершение и передача
- Отчёт в папке задания/эксперимента: README, REPORT, тесты, малые разрешённые results, точный SHA и git status. При смене агента — [HANDOFF](docs/templates/HANDOFF.md). Для новых заданий — [TASK](docs/templates/TASK.md); ревью — [REVIEW](docs/templates/REVIEW.md).
- Не считай предыдущий диагноз доказанным: воспроизведи проблему. Не переписывай работающий код без основания. Не требуй историю чата для продолжения.
- Владелец утверждает решения и слияние; координатор обновляет общее состояние и журнал решений после проверки. Состояние локального worktree может отличаться от GitHub. Не утверждай, что удалённый агент видит локальные коммиты, кеш или секреты.

По умолчанию выполняй только назначенную задачу. Если задания нет, сообщи фактическое состояние и предложи следующий шаг; не начинай реализацию самостоятельно.
