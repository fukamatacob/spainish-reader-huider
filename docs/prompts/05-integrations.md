# PoC 05 — внешние интеграции и локальная безопасность

Ты инженер, выполняющий один ограниченный технический эксперимент в репозитории fukamatacob/spainish-reader-huider. Прочитай SPEC.md, docs/POC_PLAN.md, docs/TECHNICAL_AUDIT.md и при необходимости docs/DESIGN_SYSTEM.md. Следуй актуальной SPEC, не историческим UX-решениям донора. Не реализуй весь продукт. Проверь git status, сохрани чужую работу, используй отдельную ветку/worktree либо уже выделенную рабочую ветку. Не пушь и не сливай main без явного указания. Не используй destructive reset. Не публикуй секреты, личные данные, большие базы/модели/APK и нелицензированные исходные данные. Для существенных загрузок/установок проверь объём и разрешение. Не запрашивай ключи в чат/логи; используй только разрешённый локальный секрет. Не выдавай результаты mock/эмулятора/предположения за live/device. При блокере выполняй независимые части, укажи точную причину и команду для продолжения.
В своей директории создай README.md, REPORT.md, код, тесты, небольшие results/ с сырыми метриками и разрешёнными fixtures. Запиши версии, SHA, лицензии, команды, exit codes, окружение, что реально проверено, отклонения и воспроизведение. В конце: PASS/PARTIAL/FAIL/BLOCKED, ADOPT/ADAPT/REJECT/NEEDS MORE EVIDENCE, перечень изменённых файлов и конкретный следующий шаг. Не отмечай эксперимент завершённым без критериев из POC_PLAN.md.

Рабочая директория: experiments/05-integrations/. Цель: изолированные проверки A–E; не делать весь UI. Раздели отчёт и тесты по подзадачам, блокер одной не останавливает остальные. Зафиксируй версии, лицензии, реальные Android dependencies.

A. CommonMark Java: проверить Android, построить минимальную Document Model (title/source/ordered chapters/blocks/stable spans/inline marks) из AST; Markdown heading, абзац, list, quote, emphasis, strong, диакритика, ссылки, безопасная обработка HTML без исполнения. Вставка/TXT: проверить TextDecoding, ImportCleaner (UTF-8/UTF-16 BOM/Windows-1252 и переносы, не разрушать структуру). 
B. Readium Kotlin Toolkit: EPUB 2/3 без DRM, метаданные/TOC/spine, извлечение текста и inline styles, длинная книга, пропуски и позиции. Проверить используемые модули API и desugaring. Повреждённые/большие архивы, лимиты, не исполнять HTML/JS и не обходить DRM. Только законные fixtures.
C. Klead + HTTP client: 20–30 публичных испаноязычных статей разной структуры/региона, список URL и даты, проверяемая ручная рубрика title/body/completeness/noise/structure/error. Не заявлять процент качества без знаменателя. Хранить URL и метрики, не полные сторонние статьи. HTTPS, safe redirects, ограничения времени/размера, отсутствие обхода paywall/login, fallback manual paste/Share. Markdown output → тот же CommonMark адаптер.
D. LLM: переиспользуемые клиенты донора; mock HTTP tests авторизации, JSON schema, timeout/cancel, errors/429/Retry-After, usage unknown, no silent fallback. DeepSeek и OpenRouter — минимальные live тесты каталога и plain/structured output только при явном разрешении владельца на запросы и согласованном лимите; ключ из разрешённого локального хранилища. Без ключа/разрешения — LIVE BLOCKED, mock отдельно. Не хранить raw prompts/answers/credentials в логах, не вызывать LLM при импорте/обычном тапе, не создавать LookupEvent. Тест banco в контрольном предложении не измеряет общее качество.
E. Android TTS и Keystore: список es voices и network requirement, произношение слова/предложения на реальном телефоне в airplane mode; encrypted marker, decrypt после перезапуска, удаление, invalidation/error, исключение секретов из backup, HTTPS для cloud. Не использовать реальный API-ключ в тесте хранения. Указать метод проверки и ограничения.

Критерии: A–C преобразуют документы в общую структуру с сохранением текста и позиций; D подтверждает контракт mock и, если разрешено, отдельный live результат; E реальные device checks или BLOCKED DEVICE. Для Alpha необходимы TXT, один LLM-профиль/защита ключей; остальные проверки не объявлять выполненными и завершить до соответствующего этапа. Составь таблицу PASS/PARTIAL/FAIL/BLOCKED по подзадачам, рекомендации по адаптерам и нерешённые вопросы.
