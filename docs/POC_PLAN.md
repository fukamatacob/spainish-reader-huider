# План технических PoC Spanish Reader

Версия 1.0 · 27 ноября 2026 г.
Статус: согласованный план экспериментов; ни один эксперимент не считается выполненным.
Основание: [SPEC.md](../SPEC.md) v0.19 (§9.1, §12, §15–17), [TECHNICAL_AUDIT.md](TECHNICAL_AUDIT.md), [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md). При конфликте текущая SPEC и согласованные решения выше исторического аудита.

## Цель и границы

До продуктовой реализации проверить риски: выборочный перенос из MIT-донорского проекта awkay/spanish-reader, офлайн-словарь, контекстный NLP, интерактивный Compose Reader, интеграции. Результат — воспроизводимый код, тесты, сырые метрики, отчёт и предложение решения. Не начинать реализацию Alpha целиком. Новый Android-проект, без обязательного backend. Не объявлять тесты пройденными без фактического запуска.

Целевое окружение: MacBook Pro M2/Apple Silicon; Android ARM64, Samsung Galaxy S25 Plus. Записать реальную версию ОС, SDK/JDK/Gradle/AGP, ABI, firmware, свободное место, параметры сборки. Не подменять замеры телефона результатами JVM или эмулятора; если телефона нет — отметить BLOCKED DEVICE, дать команды adb и процедуру ручной проверки.

Перед загрузками/установками с существенным расходом диска/трафика сообщить объём и получить разрешение, если не дано.

## 01 — исходный донор

Зафиксировать upstream commit (не SHA дерева), LICENSE и notices; чистая сборка Gradle wrapper, core/app unit tests, instrumented tests при наличии устройства. Перечень задач уточнить через gradlew tasks/projects. Не чинить донора скрытно: сначала исходный результат, затем минимальный изолированный workaround с diff. Не переносить Go/web/sync/OCR/drills. Проверить tokenizer, segmenter, PhraseLocator, TextDecoding, ImportCleaner, LLM-клиенты/JSON, DeviceTts, BackupCodec; указать reuse/adapt/rewrite/exclude с доказательствами, зависимостями и тестами. Выход: команды, exit codes, APK path/размер при сборке, тестовые отчёты, зависимости и риски.

## 02 — словарь

Kaikki/Wiktextract + Doozan Spanish Data как кандидаты, испанский → английский. Pin дата/URL/commit, SHA256, лицензия кода и отдельно данных/моделей, происхождение, требования attribution/share-alike. Не считать число sense records числом уникальных лемм. Проверить реальные форматы; Python ETL на Mac, без Python runtime на Android. Потоковое чтение JSONL, Unicode NFC/case normalization без потери диакритики, сохранение исходных форм. Таблицы-кандидаты lexemes/senses/forms/expressions/examples/frequency; many-to-many формы/леммы, POS, provenance, региональные пометки, значения, стабильные связи внутри версии, индексы. Не объединять омонимы по форме. Кандидаты по словоформе, консервативный baseline без контекстного NLP: deterministic ranking (частотность/правила, задокументировать). Не угадывать отсутствующие признаки. Воспроизводимая сборка, integrity_check, EXPLAIN QUERY PLAN, тесты диакритики/клитик/voseo, измерение размера и памяти. Проверка SQLite на Android, не только sqlite3 на Mac.

## Корпус и метрики (02–03)

Первый corpus v0: 200–500 вручную размеченных токенов из разрешённых для использования или собственных текстов, цель A2/взрослая тематика; отдельно challenge set (vino, fui, hice/hicieron, dímelo, hubiéramos llegado, vos tenés, guagua, darse cuenta de, banco). Разные регионы: Мексика, Аргентина, Колумбия, Испания; фиксировать источник/лицензию, не выдумывать происхождение, если примеры синтетические — пометить. Формат JSONL: doc/sentence ID, текст, диапазон токена (единая конвенция UTF-16 для Android или явное преобразование), gold lemma/POS/FEATS при наличии, допустимые альтернативы, MWE span/lemma, семантическая неоднозначность. Разметка человеком/проверенная человеком; LLM-only gold не считать валидированным. Держать отдельный holdout по документам, зафиксировать до настройки правил; если недоступна независимая проверка — статус preliminary. Не размечать по предсказаниям тестируемого движка. Одинаковые входы и знаменатели, отдельно обычный и challenge. Отчёт: numerator/denominator, ошибки по категориям, unknown/abstain и ложные уверенные ответы. Для MWE precision/recall/F1 по заранее заданным границам; morph по доступным gold; не засчитывать guessed sense как достоверный.

Предварительные ориентиры (не гарантии и не основание объявить провал без анализа):
| Метрика | Ориентир |
|---|---|
| Candidate lemma coverage | ≥95% размеченных токенов с леммой |
| Top-1 lemma | ≥90% на обычном корпусе |
| Top-1 POS (единая схема UPOS) | ≥90% |
| Прогретый SQLite lookup p95 | ≤50 мс |
| NLP-анализ типичного предложения p95 | ≤200 мс |
| Потеря/искажение исходного текста | 0 в тестах |

Метрики POS/lemma: неправильные и abstain входят в знаменатель; дополнительно conditional accuracy и coverage. Микро-корпус не доказывает обобщение на весь язык. MWE/FEATS, cold start, RAM, APK/DB/model size, энергопотребление — сначала измерить, затем согласовать пределы. Timing: real ARM64, airplane mode для offline, отдельно cold/warm, фиксировать сборку/устройство/длину входа, не менее 100 запросов или 100 повторов с описанием выборки и warm-up, p50/p95, отдельное измерение IO/load/inference, не включать случайные задержки сети. Для cold start несколько независимых запусков процесса с описанием. RAM — adb dumpsys meminfo/подходящий профилировщик, метод записать. Не изобретать confidence, если модель его не возвращает.

## 03 — contextual NLP

SQLite-only baseline против OpenNLP 2.x (проверить JVM/Android и конкретные испанские модели) и UDPipe 1 (NDK/JNI ARM64, лицензия выбранной модели). Apertium — резервный кандидат, если морфология/клитики не покрываются или первые два варианта непрактичны. Не выбирать по документации, не тащить три движка в продукт. Сопоставлять токены анализатора с исходным текстом без изменения содержимого; UPOS mapping, признаки и clitics spans. Измерить качество на одном корпусе и holdout, размер/память/скорость/лицензию/сложность интеграции. Важно: POS и lemma не решают смысловую неоднозначность banco/fui; показывать варианты, сохранять статус uncertainty, не создавать учебных событий. Выход: сравнение и рекомендация с trade-offs; если нет приемлемого кандидата — предложить следующий конкретный эксперимент, не отменять обязательный NLP без согласования.

## 04 — Compose Reader

Отдельный маленький Android harness, реальный TextLayoutResult/offset mapping, видимый стабильный layout. Stub словаря с фиксированными данными и управляемой задержкой; никакого оплачиваемого API. Текст — абзацы, длинные предложения, переносы, диакритика, punctuation, italic/strong, выражения, края экрана. Single Tap сразу показывает результат, второй тап по тому же слову в double-tap window раскрывает карточку без повторного lookup, поздний повтор закрывает, Long Press выбирает выражение, другой тап переключает, swipe/outside закрывает, скролл не создаёт lookup. Не позволять позднему async ответу заменить новый фокус. Popover только перевод + раскрытие, над словом или под ним, без reflow/dim; синий фокус #BFD9F3, постоянный плоский янтарный marker #F3E7BC и слабее. Проверить before/after bounds, переносы и сохранение якоря при font scale/повороте/перезапуске; тест hit-testing, край/многострочность, доступность. Прототип не обязан решать финальную геометрию карточки или пороги затухания. Выход: тесты, скриншоты/запись с устройства (без личных данных), сравнительные bounds, список открытых проблем.

## 05 — интеграции

Подзадачи A CommonMark, B Readium, C Klead, D LLM, E TTS/Keystore. Для A–C единая минимальная Document Model: title, source, ordered chapters, stable blocks/spans, inline marks; не изменять спецификацию модели без решения. MD заголовки, списки, emphasis, цитаты; EPUB 2/3 без DRM, оглавление/порядок spine, длинная книга, повреждённый архив/лимиты; Klead 20–30 испаноязычных публичных URL, сравнить извлечение вручную по заранее выбранным критериям (title/body/completeness/noise/structure/error), не хранить полные статьи, не обходить paywall/защиту, ограничить время/размер/редиректы, https/allowed schemes. Зафиксировать версии, лицензии, зависимости и работоспособность Android. 
LLM: mock HTTP обязательные тесты, при разрешении владельца и предоставлении ключа из безопасного локального хранилища — DeepSeek и OpenRouter минимальные реальные запросы, каталоги, plain/JSON, error/timeout/cancel, usage; проверка ID/метаданных, не считать ответы тестом общего качества. Не использовать ключи из Git/истории/чужих аккаунтов, не делать платные/фоновые запросы без явного разрешения и согласованного лимита; при отсутствии ключа LIVE BLOCKED, mock не выдавать за live. TTS: список доступных es voices, offline voice, слово/предложение на устройстве, airplane mode. Keystore: encrypt/decrypt тестовый несекретный marker, перезапуск, удаление, invalidation/error, исключение из backup, не печатать секреты; проверить HTTPS/fallback. 
Результаты каждой подзадачи отдельные; не блокировать остальные при отсутствии API/телефона/сети.

## Формат отчёта и gate

В REPORT.md: ID, commit/SHA окружения, версии и лицензии, гипотеза, точные команды, выполненные тесты с exit codes, где запускались, ссылки на raw results, числитель/знаменатель и методика, реальные измерения, отклонения, ограничения, воспроизведение, предложение (ADOPT / ADAPT / REJECT / NEEDS MORE EVIDENCE), status PASS / PARTIAL / FAIL / BLOCKED. PASS только по выполненным условиям, mock/synthetic/expected отдельно от измеренных. Не коммитить большие или запрещённые артефакты. Сохранить ошибки и отрицательные результаты.

Gate перед Alpha: 01 — воспроизводимая сборка или документированное ограничение с работающей альтернативой; 02–03 — реально работающий офлайн-словарь и контекстный NLP на ARM64 с проверенными метриками/лицензиями; 04 — доказано отсутствие reflow, конфликтов ключевых жестов и ложных lookup на целевом устройстве; 05 — для Alpha проверены TXT и один LLM-профиль/защита ключей, остальные интеграции проверяются до соответствующего этапа. Не блокировать разработку независимыми экспериментами, но не считать неподтверждённое обязательное требование выполненным. После gate: архитектура User Database и идентичность событий, схема миграций, план переноса, затем декомпозиция Alpha. Решения утверждает владелец, результаты записываются в журнал.
