# Фактическая архитектура

Статус на 27 ноября 2026 г.: исходная точка, фактическая продуктовая реализация пока не подтверждена. Этот документ предназначен для описания работающего кода по мере появления, а не для дублирования SPEC.md.

## Проверенные факты

- Утверждённая цель: новый Android Kotlin/Jetpack Compose проект, выборочный перенос из MIT-донора. См. SPEC.md §12, §14–15.
- Имеется статический аудит донора: TECHNICAL_AUDIT.md. Это описание изученного upstream, а не архитектуры нашего приложения.
- В SPEC.md v0.20 утверждены offline-first языковое ядро, разделение языковых/пользовательских данных/кеша, прямые LLM API по явному запросу и отсутствие обязательного backend.
- Фактический результат локальной сборки донора и структура нового приложения пока не подтверждены. Не объявлять модули, зависимости и схемы реализованными.

## Обновлять после PoC

Для каждого реально появившегося модуля:
- Путь, commit SHA, назначение, публичные интерфейсы, входы/выходы.
- Направление зависимостей, данные и их владельцы, async/cancellation, failure modes.
- Команды сборки/тестирования и ссылки на результаты.
- Что перенесено из upstream: ссылка на UPSTREAM.md, SHA, изменения и лицензия.
- Ограничения, несовпадения с SPEC и связанные технические решения.

Планируемые контракты помечать PROPOSED, эксперименты — EXPERIMENTAL, подтверждённые реализации — VERIFIED с доказательствами. Не описывать целевую архитектуру как фактическую. Окончательный выбор NLP, структура User Database и миграции после соответствующих PoC и согласования.
